# Security Policy

Vex Hospital welcomes good-faith reports about vulnerabilities in the Hospital protocol, machine-readable controls, playbooks, verification mechanisms, privacy boundaries, or authorization gates.

## Please report

Examples include:

- authorization or state-transition bypasses;
- instruction-precedence or prompt-injection weaknesses;
- evidence or verification forgery;
- privacy or secret leakage caused by Hospital behavior;
- unsafe treatment behavior;
- ways to make the protocol conceal material residual risk.

## Disclosure safety

Do not place credentials, private patient data, private repository details, or working exploits against real patient systems in a public issue.

Use GitHub's private vulnerability reporting/security-advisory mechanism when available. If a safe private channel is unavailable, disclose only enough publicly to indicate that a private security contact is needed.

## Research boundaries

Good-faith testing should use systems you own or are authorized to test, minimize harm, avoid unnecessary data access, and stop when continued testing could create consequential effects outside the authorized scope.

## Scope

A security report about Vex Hospital is not automatically evidence that a patient system is compromised. Hospital vulnerabilities and patient vulnerabilities are separate findings and should be assessed independently.
